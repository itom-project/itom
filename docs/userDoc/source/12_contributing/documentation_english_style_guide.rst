Documentation English Style Guide
#################################

Purpose
*******

This guide defines the English writing style for the itom documentation.
It is intended to improve consistency, readability, and maintainability.

General rules
*************

1. Use clear, simple, and direct sentences.
2. Prefer active voice over passive voice.
3. Keep terminology consistent across all pages.
4. Use the same term for the same concept everywhere.
5. Use sentence case for headings.
6. Use US English spelling consistently.

Project-specific terminology
****************************

Use the following terms consistently:

* ``itom`` for the project/product name.
* ``Python`` (not ``python``) for the language name.
* ``Qt Designer`` (not ``QtDesigner``) for the tool name in prose.
* ``LabVIEW`` for the software name.
* ``Institut für Technische Optik`` for the institute name.
* ``on the internet`` (not ``in the internet``).

Style for technical text
************************

1. Prefer concise wording:

   * ``learn how to`` instead of ``learn about to``
   * ``is an extract`` instead of ``in an extract``

2. Avoid filler phrases like ``the good thing is that`` where possible.
3. Use hyphenation for compound adjectives before nouns (for example ``script-based approach``).
4. Keep examples and code explanations close to the related commands.

Links and references
********************

1. Prefer stable, canonical URLs.
2. Avoid outdated hosts if current official URLs exist.
3. Ensure each external link has meaningful surrounding context.

Checklist before merging documentation changes
***********************************************

1. Terminology follows this style guide.
2. Spelling and grammar are checked.
3. Internal references resolve correctly.
4. External links are valid.
